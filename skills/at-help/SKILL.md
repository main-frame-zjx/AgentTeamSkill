# AT_help

角色工作记忆按六个槽位组织。回答“到哪里找以前的方案”时，优先引导用户检索个人库；跨角色检索可用 `scope: project`，浏览项目笔记可打开库内的 `00-项目学习导航.md`。

从当前目录或用户指定的目录运行 `python -B -X utf8 "<本技能目录>/../at-init-team/scripts/at.py" help --root "<目录>"`。入口只读，也适用于尚无 AT.json 的目录。

先按返回的 `catalog` 输出完整技能表，列出调用名、具体用途和典型使用时机。然后只给一个首选动作，写出判断依据、相关角色或需求以及一条可复制的调用示例。帮助请求到推荐为止。

- 角色目录若有未处理消息，优先推荐 `$at-work`；单纯查看收件用 `$at-receive-message`，核销和发送提醒用 `$at-reply-message`。项目总数按接收者计数，返回 warnings 时说明统计覆盖范围。
- 用户泛问下一步时采用 `recommendation`，从 `tasks` 补充同一优先级可处理的任务、标题和编号。项目根优先待验收、其次处理中、最后新需求。角色目录按验收人或执行人筛选，避免让其他角色代办。
- 用户已说明目的时优先匹配目的。已有明确工作项和分工用 `$at-add-worklist`；需要多人讨论取舍用 `$at-team-discuss`；修改验收条件、记录阻塞用 `$at-manage-workspace`；迭代长期职责用 `$at-update-team-member`。
- 交接角色的六槽位工作记忆用 `$at-manage-memory`，在验收或阶段收口时为初学者整理系统设计或可复用方案笔记用 `$at-manage-library`，查看团队全局进度用 `$at-start-board`。若某个任务已记录阻塞且用户希望继续执行，先了解恢复所需输入。
- 用户明确希望从当前 Agent 卸载这套技能时，推荐 `$at-uninstall`（DeepSeek Harness 中为 `/at-uninstall`），说明它会逐名检查注销结果。
- 会议从返回的项目根发起，需要 Ultra、主持人和至少一名其他角色。只有一位角色又想开会时，先推荐 `$at-add-team-member`。默认主持人为项目负责人；该角色尚未登记时可从现有角色指定。
- 发布需求应区分甲方总览、程序包和用户指南。迭代中可制作总览，正式发布由项目负责人或已授权管理角色核查目标版本的验收和交付证据。当前版本已正式发布且用户要规划下一轮时，推荐开会或为明确事项建单。
- 目录非空且没有项目时，说明应切换到已有项目或使用新空目录；数据异常时列出返回的文件路径和原因。仍可介绍技能或推荐独立看板，不把异常当作零角色或零需求。
