# AT_manage_memory

1. 用 `memory-read` 读角色的交接记录。对照需求、纪要和实际交付。没有实质变化就结束。过程流水和测试明细留在需求记录或报告中。
2. 用三句话写清主攻目标、已到哪一步、下次从哪里开始。用 `memory-patch` 提交有变化的条目，为决定和风险附上来源。每项风险写明依赖方和可核实的解除条件。需求归档后复核相关约定，仍生效的继续保留。
3. 全文限 6,656 字节（6.5 KiB），决定最多 12 条，风险最多 6 条。满额先合并同义项，再退役失效决定或已解除的风险。
4. 需求进展和个人库索引随业务操作自动刷新。提示同步中断时用 `memory-sync` 重试。遇到人工修改，先读差异、合并原意，再提交。要查一个决定为何移除或某次封版时的交接内容，用 `memory-history`。

CLI 入口位于本技能的 `../at-init-team/scripts/at.py`。工作目录为角色目录时可省略 `role`，在项目根运行时传角色名。字段、配额与重试示例见[工作记忆与个人库接口](../at-init-team/references/memory-library.md)。
