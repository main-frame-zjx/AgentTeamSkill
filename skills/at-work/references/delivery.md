# 团队代码交付与阶段报告细则

本说明补充 `$at-work` 第 4、5 步的操作细节。共用 CLI 入口与 JSON 传参约定见 [命令接口](../../at-init-team/references/commands.md)。

## 团队代码交付与冲突处理

- 团队代码工作树位于 `AT_<角色名>/repository/<团队仓库目录名>/`（目录名取自 `AT.json` 中 `team_repo` 的最后一段）。
- **开工前体检与提前同步**：开始改动前先核对 `work-context` 返回的 `worktree` 状态。若 `clean` 为 `false`，先查清未提交改动来源，避免把无关文件混入本次需求；工作树干净后尽早运行 `sync`（角色目录可省略 `role`，项目根传 `role`）合入远程 `main`，减少后续冲突。
- **提交与验证**：在角色分支只提交本次需求相关文件，排除他人改动。提交后调用 `sync`，脚本合入远程 `main` 并返回 `test_this_commit`；务必对该确切提交运行测试与人工检查。
- **合并推送**：调用 `deliver` 传入 `role`（角色目录可省略）、`tested_commit` 与 `checks[]`，将已验证提交快进合并到本地 `main` 并推送。
- **冲突与推送失败**：若 `main` 前进或 `push` 被拒，保留角色分支提交，再次 `sync`、处理冲突、重新自测后重试 `deliver`。若远端保护策略阻止直推，用 `note` 记录阻塞，不要绕过保护策略。
- **独立仓库**：不在共享团队仓库中的独立工作，在对应本地仓库提交，并将仓库路径与提交 SHA 记入需求证据。角色档案、记忆与任务历史由脚本提交到 `AT_<角色名>/` 自己的本地 Git 仓库。

## 离线 HTML 报告与阶段成果归档

- **离线 HTML 报告**：将可离线浏览的完整报告写入独立临时目录，入口为 `index.html`，样式、脚本与图片全部使用相对路径（不依赖外网资源或 `<base>`）。调用 `publish` 打包到 `AT_<角色名>/report/`：

```json
{"role":"高级客户端工程师","name":"碰撞测试-第一版","source":"D:/temp/report"}
```

  在角色目录执行可省略 `role`；在项目根执行传已确认的 `role`。归档完成后从返回的外部 HTML 入口打开核验，重点检查动态脚本装载与本地图片显示。
- **其他格式成果**：调用 `report-dir` 获取 `AT_<角色名>/report/` 目录路径，将阶段文档、测试记录、媒体素材或试玩包放入该目录，并把相对项目根的入口路径记入需求送验证据。
- **项目级发布**：需要交付面向外部的 Windows 程序包、用户指南或甲方总览时，由项目负责人或已授权管理角色通过 `$at-publish` 发布到公共 `publish/bin/`、`publish/user/` 或 `publish/dev/`。
