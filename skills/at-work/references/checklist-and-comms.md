# 本轮工作清单

开工时按需求稳定 ID 合并自有需求、pending_reviews、收件及 missing_notifications，保留所有消息 ID，并列出未关联需求的专题待办。用户指定范围优先。收件优先级依次为 P0 打回、P1 送验、P2 反馈与协作、P3 同步。现任验收人以需求有效值为准。自己验收的任务直接列入清单。

| 清单项 | 收尾核对 |
|---|---|
| 工单与对应收件 ID | 每项记为已完成、受阻或本轮未处理，附证据与下一步。 |
| 本轮送验、退回及上轮漏发事件 | 使用实际事件 key，每个事件仅提醒一次。已归档或已改派的旧提醒先查流转记录，核实本人已无后续责任后如实核销。 |
| 通讯、记忆和终检 | 对照回执检查是否漏通知、漏核销；核对工作树、交付提交和交接记忆。 |

开工收集漏发事项，收尾结算前查同群历史，按相邻流转事件与消息的 event_key 核对送验轮次。将仍有效的漏发和本轮新流转一起结算。遇到结果未知的请求时，复用原正文与幂等键重试，取得回执后再勾销清单项。

缺少必要环境时记录阻塞，保持原收件 pending。验收角色只处理指定自己验收的需求。退回或重新送验需要回复时，将原消息和关联回复一起结算；独立验收已结算的事项使用原回执。
