# AT_work

本轮需要整理工作时，使用当前角色的 `report/` 保存阶段成果。管理角色通过 `$at-publish` 交付版本程序包、用户指南或迭代中的甲方总览。

1. 根据明确指定的角色、任务所属角色或当前角色目录确定身份。若在项目根且有多个可能角色，询问用户。先读该角色的 `Agent.md`、`Memory.md`。如角色的 `.agent/` 中已有匹配当前工作的个人技能，按需读取。
2. 用 `list` 在启动时取得 `1新需求`、`2处理中` 的任务快照。有指定文件时，解析真实路径，从清单精确匹配；给编号时用 `show` 核对角色和状态，拒绝越界路径或其他状态。无指定时先续做处理中，再做本轮已有的可执行新需求；根据依赖和项目进度选序。阅读需求当前有效条件和追加历史，按需检索角色 Obsidian 知识库。
3. 调用 `$at-manage-workspace` 开始任务。遇阻时用 `note` 记录阻塞、所需输入和可恢复位置，可继续其他可做项。保留未完成状态；同一轮末尾列出仍阻塞的条目。
4. 团队代码在 `AT_<角色名>/repository/<团队仓库目录名>/`（目录名取自 `AT.json` 中 `team_repo` 的最后一段） 的角色分支上开发。按需求提交相关文件，排除别人的改动。用 `sync`（输入 `role`）合入远程 main 后，对返回的确切提交运行适当的测试及人工检查。用 `deliver` 输入 `role,tested_commit,checks`，将已测版本合并到本地 main 并推送。若 main 前进或 push 被拒，保留角色提交，同步、处理冲突、重新验证并重试。远端保护策略阻止推送时记录阻塞，避免绕过保护。独立工作在对应本地仓库提交，记录仓库位置与 SHA。角色档案和任务历史提交到该角色自己的本地仓库，交付证据记录在需求文件中。
5. 需要报告或文档时交付完整成果。默认把可离线浏览的报告写入临时独立目录，入口为 `index.html`，资源使用相对路径，然后调用 `publish`，从角色目录自动识别身份，从项目根传已确定的角色，例如 `{"role":"高级客户端工程师","name":"碰撞测试-第一版","source":"D:/temp/report"}`。从返回的外部 HTML 入口打开验证，尤其检查脚本动态装载和图片。整理其他格式时调用 `report-dir` 获取目录，将阶段文档、测试记录、媒体和试玩包放入 `AT_<角色名>/report/`。把项目根相对入口记入需求。管理角色通过 `$at-publish` 将项目级成果发布到公共的 `bin/`、`user/` 或 `dev/`。
6. 核实交付成功后调用 `$at-manage-workspace` 移至待验收，附实际测试、提交 SHA、交付物相对路径。完成本轮后依次调用 `$at-manage-memory`、`$at-manage-library`；即使无新知识也评估一次。汇报已送验、仍阻塞的需求及交付入口。

共用入口位于本技能目录的 `../at-init-team/scripts/at.py`。 将它解析为绝对路径后，从用户的项目上下文运行 `python -X utf8 "<入口>" <命令> --root "<项目目录>" --input "<UTF-8 JSON文件>"`。只读空输入可省略 `--input`。[命令接口](../at-init-team/references/commands.md) 给出了字段和重试约定。
