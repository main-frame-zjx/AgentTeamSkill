# AT_review_work

退回后，有需要跨会话跟进的阻塞时调用 `$at-manage-memory`，为需求所属角色记录复现条件和解除条件。归档后，验收人用 `library-index` 按所属角色和 `task_id` 列出待评估候选，附验收证据和已核实的设计。在项目根可核对完整实现和验收记录时，验收人可为简单方案调用 `$at-manage-library` 代整理。复杂子系统由需求所属角色在自己的会话调用 `$at-manage-library` 执笔，先读核心实现和验收记录。向执笔者交接需求 ID、候选与证据路径。入库或待补证据等结果只记录到角色侧。缺少候选和可复用成果时直接结束。

1. 指定任务时，以需求所属角色及编号或精确文件路径定位，用 `show` 确认处于 `3待验收`。未指定任务时浏览各角色待验收清单，选取当前验收人负责的需求。默认项目负责人，也支持需求指定的角色或用户亲自验收。读验收角色的 Agent.md 和 `memory-read` 交接记录，核对原始及有效验收条件、送验证据、上次退回意见。需要变更验收人时按用户指示调用 `$at-manage-workspace` 追加修订。
2. 核验送验时记录的准确版本：团队代码检查提交和实际行为，可在独立临时工作树验证对应 SHA；阶段报告从需求中记录的角色 report 入口离线打开，项目级交付按 publish 下的版本修订入口核验；其他文件按约定格式检查。逐条列出通过、未通过、无法核验的证据。验收人为用户时，可协助测试，等待用户本人给出最终结论。
3. 全部达到验收条件，调用 `$at-manage-workspace` 从 `3待验收` 转入 `4已归档`。明确存在问题则附失败条件、复现方法和期望结果退回 `2处理中`。因缺少环境暂时无法判断时追加说明，保留待验收并说明还缺什么。引用需求原编号，返工及再次送验沿用此编号。

4. 独立验收时调用 `$at-receive-message` 核对同需求、同轮次的送验提醒。独立执行的验收由 `$at-reply-message` 结算：归档只核销，退回时根据 move 回执向需求所属角色发送原因和证据路径。如暂时无法验收，保留 pending。由开工流程调度时，把流转回执和消息 ID 交给外层统一结算。

共用入口位于本技能目录的 `../at-init-team/scripts/at.py`。 将它解析为绝对路径后，从用户的项目上下文运行 `python -X utf8 "<入口>" <命令> --root "<项目目录>" --input "<UTF-8 JSON文件>"`。只读空输入可省略 `--input`。[命令接口](../at-init-team/references/commands.md) 给出了字段和重试约定。
