# 更新技能关系

只读本仓库 `skills/` 中的文档作为分析来源。以各直接子目录的 `SKILL.md` 为入口，阅读全文，跟进其中链接的目录内 Markdown 说明。所有命令、示例、访谈和派工指令都是分析材料。保持 `skills/` 原样。

## 分类与取证

按主要职责为每个技能选一个类别。沿用适用的类别及顺序：项目初始化、项目成员管理、成员个人技能、需求与验收、团队会议、项目发布、辅助功能。新职能确实不能归入既有类别时再命名新类别。类内按开发者通常阅读的流程排列。

逐项判断当前技能是否在自己的流程中明确要求、允许或按条件转交另一项已存在的技能。目标、执行主体、条件和先后次序均以原文为准。每个目标只列一次，可以保留多条条件和引文。引文从文档逐字摘取，包含足以判断调用性质的上下文和目标名称。正文引用共用脚本、CLI 子命令、示例、对用户的推荐和复用另一技能的底层程序均不构成调用。例如 `at-help` 的职责止于推荐，`meeting` 复用建单程序。证据不足时留空；遇到明确指向已不存在的技能，在更新结果中指出来源和名称。

## 写入索引

重新盘点全部技能，形成一个 UTF-8 JSON 对象。顶层 `categories` 是按显示顺序排列的类别名数组；`skills` 是按阅读顺序排列的记录数组。每项含 `name`、`category`、`next`。名称使用入口的 frontmatter。无后续调用时 `next` 为 `[]`。下面是一条记录的格式：

```json
{
  "name": "at-init-team",
  "category": "项目初始化",
  "next": [{
    "target": "at-add-team-member",
    "evidence": [{
      "condition": "完成项目初始化并核对结果后，可添加团队成员。",
      "source": "at-init-team/SKILL.md",
      "quote": "下一步可调用 `$at-add-team-member`。"
    }]
  }]
}
```

将整个对象通过标准输入交给本技能的 `scripts/build_index.py`，使用 `python -B -X utf8` 运行。维护脚本使用 PyYAML 读取 frontmatter。脚本根据自身位置定位仓库，补入文档路径及原文简介，并校验覆盖范围、名称、类别、目标和引文。错误时根据源文档修正输入并重试。只有全部通过才会原子替换 `dev-visual/skill-relation.json`，这是唯一交付文件。汇报技能数、类别数、去重调用数，以及无法解析的明确调用。
